## 要做什麼

在 Cloud SQL 上執行一份 SQL 腳本：[`002_split_freight_tables.sql`](./002_split_freight_tables.sql)（與本文件同資料夾，也在 GitHub repo `database/migrations/` 內，commit `95204a1`）。

## 為什麼

KPL 儀表板的運費資料從「每倉每日一筆總額」升級為「每車一筆明細」，拆成主線 / 非主線兩張表。新版程式（已部署）會查這兩張新表，**表還沒建，所以目前「資料匯入」頁的狀態表會載入失敗**。

## 操作步驟

1. 開 Cloud SQL Studio：
   https://console.cloud.google.com/sql/instances/l000-db/studio?project=l000-493901
2. 登入資料庫 `L000-DB`（使用者 `L000LDB`）
3. 把 `002_split_freight_tables.sql` **整份**貼進查詢視窗執行
4. 看到執行成功（COMMIT）即完成

## 這份 SQL 會做的事

1. **DROP `kpl_dashboard.freight_daily`**（舊運費表）
   - ⚠️ 唯一破壞性操作。舊表內資料會消失 — **已確認不需保留**，新格式 Excel 會重新上傳。
2. 建新表 `freight_mainline_daily`（主線運費，47 欄）
3. 建新表 `freight_non_mainline_daily`（非主線運費，含自動分類欄位）
4. 放寬 `import_batches.source_type` 的 CHECK constraint（允許新類型）

全程包在 `BEGIN ... COMMIT` 交易內，中途失敗會自動 rollback，不會留下半套狀態。建表都用 `IF NOT EXISTS`，重複執行安全。

## 驗證（執行完跑這段）

```sql
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'kpl_dashboard'
  AND table_name LIKE 'freight%';
```

預期結果：`freight_mainline_daily`、`freight_non_mainline_daily` 兩列（`freight_daily` 應消失）。
